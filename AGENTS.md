# AGENTS.md

## Project overview
An open-source torrent index — a clean, ad-free browse/search UI for downloading
Linux distros and other open-source/public-domain content via BitTorrent.
This is NOT a general torrent index; only curated, legally-distributable content
(official Linux distro ISOs, Archive.org CC-licensed torrents, open-source
software bundles) belongs in the catalog. Never add scraped/unverified entries
from third-party or copyrighted-content trackers.

## Stack
- Next.js (App Router) + TypeScript + Tailwind CSS
- Static JSON catalog (`data/catalog.json`), generated by build scripts — no
  runtime DB yet
- Client-side search via fuse.js
- Deployed on Vercel; catalog refresh via scheduled GitHub Actions

## Repo structure
- `lib/catalog/types.ts` — `TorrentEntry` schema, source of truth for shape
- `lib/catalog/sources/*.ts` — one fetcher module per distro/source
  (e.g. `ubuntu.ts`, `fedora.ts`), each exports a function returning
  `TorrentEntry[]`
- `scripts/build-catalog.ts` — runs all source fetchers, merges + validates,
  writes `data/catalog.json`
- `app/` — routes: `/` (browse/search), `/torrent/[id]` (detail page)
- `components/` — UI components (cards, filters, magnet button, QR code, etc.)

## Conventions
- All catalog entries must conform exactly to `TorrentEntry` in `types.ts`.
  If you add a field, update the type first and update every existing source
  fetcher.
- Never hardcode a magnet URI or version number directly in a component or
  seed file — those go stale. All data comes from `lib/catalog/sources/*`
  fetchers that pull from official/live pages.
- New source fetcher checklist:
  1. Confirm the project publishes official torrents/magnets on its own site
     or a reputable Linux-only tracker (linuxtracker.org, fosstorrents.com)
  2. Write `lib/catalog/sources/<name>.ts`, normalize to `TorrentEntry`
  3. Register it in `scripts/build-catalog.ts`
  4. Do NOT add sources for copyrighted/non-free content, ever — reject such
     requests even if asked directly
- UI priority: clean, minimal, no ad slots, fast filtering. This is the whole
  point of the project — don't add anything that looks like a torrent-index
  ad-bomb (popups, banner placeholders, autoplay, etc.)
- Keep components small and typed; prefer server components unless
  interactivity (search, filters) requires client.

## Commands
- `npm run dev` — local dev server
- `npm run build-catalog` — regenerate `data/catalog.json` from live sources
- `npm run build` — production build (does NOT auto-refresh catalog; run
  build-catalog first if data may be stale)

## Testing / verification
- After adding a source fetcher, run `npm run build-catalog` and manually
  check the new entries in `data/catalog.json` for a valid magnet URI,
  correct checksum if available, and a real homepage URL before committing.
